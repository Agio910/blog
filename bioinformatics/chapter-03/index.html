2. 第一节 分子序列数据库概述

2.1 记录、注释与两类数据库【必须掌握】

分子数据库由记录（entry）构成，每条记录包括原始序列和描述它的注释（annotation）：物种、来源、基因名、特征坐标、功能、文献。对一条刚测出来的序列，往往只知道物种和组织来源，注释决定了它能被怎样使用，所以教材强调注释和序列同等重要。

表 3.1 主要分子数据库分类（教材 p.54–55）

类级 数据类型 举例
初级 核苷酸序列 GenBank
初级 蛋白质序列 Swiss-Prot
初级 蛋白质结构 PDB
二级 注释基因序列 NCBI RefSeq
二级 蛋白质功能域 Pfam

初级数据库（primary database）直接收存实验得到的序列或结构；二级数据库（secondary database）在初级库和文献的基础上加工、归纳，服务于特定用途，如 RefSeq、Pfam、启动子库。这个二分法今天要加两点限定。其一，表里把 Swiss-Prot 列为初级库，但 Swiss-Prot 的每条记录都经过人工整理，性质上更接近”整理过的参考库”；真正”作者交什么就存什么”的是 INSDC 三库（§3.1）。其二，原始读段（reads）现在单独归档在 SRA/ENA/GSA，组装序列与读段属于不同层次（§1 的分层表）。

教材指出几个使用数据库时必须记住的事实。

  • 注释质量参差不齐：数据库要在覆盖面和注释深度之间取舍（TrEMBL 与 Swiss-Prot 就是两个极端，§4.1），注释也会随新发现不断修改。
  • 库里有错误。【现代实践】这一点现在有量化证据：Conterminator 对 GenBank、RefSeq 和 nr 做全库比对，发现 GenBank 中 200 多万条、RefSeq 中约 11.4 万条序列被错误标注了物种（Steinegger & Salzberg, 2020）【已核实】；NCBI 的 FCS-GX 筛查 160 万个 GenBank 基因组组装，发现 36.8 Gbp 污染序列，占总碱基的 0.16%，其中一半来自 161 个组装（Astashyn et al., 2024）【已核实】。
  • 坐标约定不统一。教材说”有的数据库以 1 为起始，有的以 0 为起始”，具体对应如下【易错】：
格式 起点 区间 例：第 687–3158 位碱基
GenBank/EMBL 特征表、GFF3、GTF 1 闭区间 [start, end] 687..3158；GFF3 第 4、5 列为 687、3158
SAM 的 POS 列（SAMv1 规范） 1 只给起点 687
BED（UCSC FAQ） 0 半开区间 [start, end) 686、3158
Python 切片 0 半开区间 seq[686:3158]，长度 2472

由 1-based 闭区间转 BED，起点减 1、终点不变；长度在 1-based 闭区间里是 end − start + 1，在半开区间里是 end − start。§7.2 的代码把同一个基因同时写成 GFF3 和 BED 行。

2.2 四种记录格式【必须掌握】

FASTA

FASTA 格式又称 Pearson 格式，来自 Lipman 和 Pearson 的 FASTA 序列搜索程序（Lipman & Pearson, 1985；Pearson & Lipman, 1988）。程序名读作”fast A”，意为 FAST-All，即适用于蛋白和核酸两种字母表，不是教材说的”A 表示联配”【易错】。

一条记录由描述行和序列行组成。描述行以 > 开头，第一个空白之前的部分通常被当作序列 ID，其余是自由文本描述；描述行之后是若干序列行，行宽没有强制规定，习惯上每行不超过 80 个字符。早期格式还允许以 ; 开头的注释行，现在基本不用。多条记录直接首尾相连。

描述行没有统一的结构，不同来源差别很大。教材图 3.1 的描述行是 NCBI 早年的竖线分隔格式 >gi|332309159|ref|NM_181652.2| Homo sapiens peroxiredoxin 5 (PRDX5), ...，其中 gi 是 NCBI 内部的数字编号。NCBI 已不再用 GI 号作序列标识（GenBank 发布说明：VERSION 行自 2017 年 3 月起不再显示 GI）【已核实】，2026-10-23 用 E-utilities 取同一条记录，得到的描述行是 >NM_181652.3 Homo sapiens peroxiredoxin 5 (PRDX5), transcript variant 3, mRNA; nuclear gene for mitochondrial product，而且版本已从 .2 变成 .3（§7.3）。写解析器时要同时考虑两种描述行；序列里的小写字母常表示被软屏蔽（soft-masked）的重复序列，N 表示未知碱基，解析时不要随手转成大写或丢掉。

FASTQ

FASTQ 在 FASTA 的基础上给每个碱基附一个质量字符，一条读段固定四行：

  1. @ 开头的读段名与描述；
  2. 碱基序列；
  3. + 开头的分隔行，后面可以重复读段名，也可以为空，但 + 本身不能省；
  4. 质量字符串，长度必须与第 2 行相同，逐位对应。

质量字符串里的每个字符编码一个质量值。若测序错误率为 \(e\)，Phred 质量值定义为（式 3.1，教材写作 \(Q_{\text{phred}}=-10\lg e\)，lg 即常用对数）：

\[ Q_{\text{phred}} = -10\log_{10} e, \qquad e = 10^{-Q_{\text{phred}}/10} \]

所以 Q10、Q20、Q30、Q40 分别对应错误率 10%、1%、0.1%、0.01%，每增加 10，错误率降为原来的十分之一。一条读段的期望错误碱基数是 \(\sum_i 10^{-Q_i/10}\)，这比”平均质量值”更直接地反映读段的可靠程度，因为对数尺度上的平均会掩盖少数极低质量的位点。

表 3.2 Illumina 测序质量与错误率对照表（教材 p.56，四行已用代码逐一验算，§7.1）

测序错误率 /% 质量值 \(Q_{\text{phred}}\) Q 值 对应字符（Phred+33）
5 13 Q13 .
1 20 Q20 5
0.1 30 Q30 ?
0.01 40 Q40 I

5% 对应的精确值是 13.01，取整为 13；字符等于 chr(Q + 33)。

质量值写进文件时要加一个 ASCII 偏移。历史上有三种变体，教材把它们混在一起了【易错】：

变体 分数定义 ASCII 偏移 可编码范围 使用时期
Sanger 标准 Phred 33 0–93 Sanger 测序、SRA 下载的数据、Illumina 1.8 及以后
Solexa / Illumina 1.0 Solexa：\(Q=-10\log_{10}\frac{e}{1-e}\) 64 −5 到 62 早期 Solexa 流程
Illumina 1.3–1.7 Phred 64 0–62 2009–2011 年前后

（依据：Cock et al., 2010【已核实】，以及同一批作者维护的 Biopython QualityIO 文档。）Solexa 分数与 Phred 分数在高质量端几乎相等，在低质量端相差很大：\(e=0.5\) 时 Phred 为 3.01，Solexa 为 0（§7.1）。拿到一批不知来源的 FASTQ，先看质量字符的 ASCII 范围：出现小于 59（;）的字符必为 +33；全部不小于 64 且出现大于 74（J）的字符多半是 +64；介于两者之间的无法单凭字符判断。把 +64 的数据当成 +33 读，每个质量值会被高估 31。

教材里的”Q20、Q30”有两种用法：说一个碱基”达到 Q30”指它的质量值 ≥30；说一份数据”Q30 为 85%”指质量值 ≥30 的碱基占全部碱基的 85%。后者是一个比例，不是错误率（勘误表第 3 行）。

教材图 3.2 是一条 HiSeq X 一类仪器的读段，读段名 @ST-E00169:117:HG2T3CCXX:4:1101:23794:1432 1:N:0:NTGTCA 是 Casava 1.8 之后的格式：空格前依次是仪器名、运行号、流动槽 ID、泳道、tile、簇的 x、y 坐标；空格后依次是读段号（双端测序的第 1 或第 2 条）、是否被过滤（N 表示未过滤）、控制位、样本条码。质量串里只出现了 #、<、A、F、K 五种字符，对应 Q2、Q27、Q32、Q37、Q42：第一个碱基是 N，质量为 Q2；其余质量值被”分箱”成少数几档，这是新型仪器为压缩数据做的质量分箱。这个例子还说明质量值的上限因仪器而异（这里到 Q42），解析时不要假定最高就是 40 或 41。

GFF 与 GTF

GFF（general feature format）用一行描述一条序列上的一个特征（基因、外显子、CDS、结合位点等），9 列，列间用 Tab 分隔。教材描述的是 GFF3，现行规范是 Sequence Ontology 维护的 GFF3 1.26 版（Lincoln Stein，2020-08-18）【已核实】，下表按规范整理：

列 名称 含义 可否为 .
1 seqid 坐标所在的序列（染色体、scaffold、contig） 否
2 source 产生该特征的程序或数据库 可
3 type 特征类型，须取自 Sequence Ontology（gene、mRNA、exon、CDS 等） 否
4、5 start、end 1-based 坐标，start ≤ end 否
6 score 浮点数，语义未统一规定；规范建议相似性比对用 E 值，从头基因预测用 P 值 可
7 strand +、-；. 表示无方向；? 表示有方向但未知 可
8 phase 只对 CDS 有意义且必须给出：0、1、2 非 CDS 为 .
9 attributes tag=value 对，分号分隔；ID、Parent、Name 等大写开头的属性名有预定义含义 可

phase 最容易误解【易错】。规范的定义是：从这个 CDS 片段的 5′ 端开始，往前数几个碱基才到下一个完整密码子的第一个碱基（正链的 5′ 端是 start，负链是 end）。它描述的是片段相对密码子的偏移，不是读码框（frame）编号；规范特意提醒两者不要混淆。若一个转录本的 CDS 由多个片段组成，后一段的 phase 可以由前一段的长度 \(\ell\) 和 phase \(\phi\) 推出（GTF2.2 规范给出的公式）：

\[ \phi_{\text{next}} = \bigl(3 - (\ell - \phi) \bmod 3\bigr) \bmod 3 \]
\(\ell-\phi\) 是前一段从第一个完整密码子起算的长度，对 3 取余就是它末尾多出来的碱基数，下一段开头还需要补齐的就是 \(3\) 减去这个余数。§7.2 用这个公式验算了 GFF3 规范示例里全部 CDS 的 phase。

GTF（gene transfer format，现行为 GTF2.2）是 GFF 的一个方言【已核实：GTF2.2 规范】。区别主要有三点：第 8 列叫 frame，但含义与 GFF3 的 phase 相同；第 9 列写成 gene_id "001"; transcript_id "001.1";，这两个属性必填；CDS 不含终止密码子，终止密码子单独记为 stop_codon（GenBank 的 CDS 则含终止密码子）。

GBFF：GenBank flat file

GenBank 的记录用 flat file 格式发布（GBFF），由描述、特征（FEATURES）和序列（ORIGIN）三部分组成，以 // 结尾。


图 3.4 GenBank 记录 U49845（酿酒酵母 TCP1-beta、AXL2、REV7 基因）。A 描述部分，B 注释部分，C 序列部分（教材 p.57）

描述部分的关键行：

  • LOCUS：记录名、序列长度、分子类型、拓扑（linear/circular）、分类代码（这里 PLN）、更新日期。教材把 LOCUS 译作”位置”不准确。GenBank 发布说明建议按空白分词解析这一行，而不是按固定列，因为 accession 和序列长度都在变长【已核实】。
  • ACCESSION 与 VERSION：accession 是稳定不变的记录号；VERSION 行是”accession.版本号”，序列每改动一次版本号加 1，注释改动不改变版本号。这套写法 1999 年 2 月启用，当时所有记录都从 .1 开始【已核实：GenBank 发布说明 3.4.7】。论文里引用序列应写 accession.version。
  • SOURCE/ORGANISM：物种名与完整分类谱系。图 3.4 的 SOURCE 写作”baker’s yeast”，2026 年取回的同一记录写作”brewer’s yeast”，而 VERSION 仍是 U49845.1，正好说明版本号只跟踪序列的变化。
  • REFERENCE：文献与递交信息。

FEATURES 区每个特征由特征键（source、gene、mRNA、CDS 等）、位置和若干 /限定词 组成。位置写法需要读懂：687..3158 是 1-based 闭区间；<1..>206 表示特征 5′ 端和 3′ 端都超出了这条序列（部分特征）；complement(3300..4037) 表示在负链；join(a..b,c..d) 表示由多段拼成（如含内含子的 CDS）。/codon_start=3 表示翻译从 CDS 的第 3 个碱基开始，相当于 GFF3 的 phase = 2；/translation 是数据库给出的蛋白序列，可以用来检验自己的解析和翻译是否正确（§7.2 对三个 CDS 做了这种检验，全部一致）。

ENA 和 DDBJ 发布的是同一套 INSDC 数据，格式在细节上不同。ENA 的 EMBL 格式用两字母行首代码：ID（对应 LOCUS）、AC、DT、DE、OS、OC、RN、FT（特征表）、SQ。同一条 U49845 在 ENA 里的 ID 行是 ID U49845; SV 1; linear; genomic DNA; STD; FUN; 5028 BP.，其中 SV 1 是序列版本，DT 行另记”Last updated, Version 6”，即条目版本（§7.3）。特征表的语法（INSDC Feature Table）三家通用。

2.3 数据库冗余与序列错误【必须掌握】

冗余（redundancy）指库里同时存在大量相同或高度相似的序列：同一基因被不同实验室重复递交，同一家族在许多物种里都被测过。教材列出三个后果：统计分析偏向被大量测序的家族；样本不再独立，相当于有偏抽样；用这些数据训练预测方法时，方法会被带偏。

从机器学习的角度，这里其实是两个不同的问题，原笔记把它们混成”等价于数据泄漏”了【易错】。

  • 训练集内部的冗余造成加权偏差：被测得多的家族（模式生物、病原体）在损失函数里权重大，模型在这些家族上好、在稀有家族上差。对策是按聚类加权或每簇只取代表。
  • 训练集与测试集之间的同源造成信息泄漏：测试序列在训练集里有近乎相同的”亲戚”，模型靠记忆就能答对，测得的准确率高估了对新序列的泛化能力。对策是按序列一致性聚类后整簇划分（§6.2、§7.5、§8.2）。

2.4 递交序列与”材料与方法”【应该理解】

期刊一般要求作者先把序列递交到公共数据库，拿到记录号（accession）后在论文中注明。教材列出 GenBank 的递交系统：BankIt、Sequin、tbl2asn、Submission Portal、Barcode Submission Tool；ENA 的 Webin 支持批量递交。

【现代实践】这份清单已经部分过时。NCBI 的 Sequin 于 2021 年 1 月停用，注释基因组改用 Genome Workbench 的提交向导；tbl2asn 已被 table2asn 取代【已核实：NCBI Insights】。GenBank Release 274.0 发布说明列出的现行工具是网页端的 Submission Portal 和 BankIt，以及命令行的 table2asn（用于完整基因组和大批量序列，生成的文件通过 Submission Portal 上传）【已核实】。原始读段递交到 SRA（或 ENA、DDBJ 的读段库），组装和注释序列递交到 GenBank/ENA/DDBJ，两者在 BioProject、BioSample 下关联。

教材强调”材料与方法”要写清数据库名称、版本和检索日期，这是保证可重复性的最低要求。实际写作时还应写上所用记录的 accession.version、软件版本与关键参数；用了整个库（如 nr、UniRef90、IMG/VR）就写明发布号。数据库的变化远比期刊出版快：UniProtKB 在 2025–2026 年改变收录范围之后，同样的检索会得到完全不同的命中集合（§4.1）。

2.5 检索：Entrez、SRS 与程序化访问【应该理解】

Entrez 是 NCBI 的综合检索系统，可以在核酸、蛋白、结构、基因组、文献（PubMed）等数据库之间统一检索并互相链接。教材图 3.5、3.6 演示了网页操作：多个关键词之间默认是 AND；关键词要有明确指向，”gene””protein”这类词没有意义；”Limits”和”Advanced”可以按物种、分子类型等限定。图 3.6B 右侧的”Search details”显示 Entrez 实际执行的查询（hemoglobin[All Fields]），这是理解检索结果的关键：Entrez 会自动把关键词映射到字段，查得不对时先看这里。

SRS（sequence retrieval system）是 EMBL 的 Thure Etzold 开发的检索系统，是 EBI 早年的主要检索入口。EBI 现在的统一检索服务是 EBI Search，ENA 另有自己的浏览器和 API【现代实践】。

批量取数据要用程序接口，不要用网页。

  • NCBI E-utilities：einfo（数据库信息与记录数）、esearch（检索，返回 UID 列表或计数）、efetch（按 ID 取记录，rettype=gb 取 GenBank 格式，rettype=fasta 取 FASTA）、elink（跨库链接）。不带 API key 每秒最多 3 次请求，带 key 每秒 10 次（接口响应头 X-RateLimit-Limit: 3；Biopython 文档）【已核实】。NCBI 建议请求里带 tool 参数标明程序名。
  • ENA：Portal API 用于检索和计数（如 count?result=sequence&query=tax_tree(10239) 统计病毒界下的序列数），Browser API 按 accession 取 EMBL 或 FASTA 格式记录。
  • UniProt：REST API 的响应头 X-Total-Results 直接给出命中条数，X-UniProt-Release 给出发布号，适合在脚本里记录版本。

§7.3 的脚本把这几种接口各调用一次，并缓存 §7.2 要用的 GenBank 记录。

3. 第二节 核苷酸序列相关数据库

3.1 INSDC、GSA 与 RefSeq【必须掌握】

国际上三个主要的核苷酸序列公共数据库是 EMBL-EBI 维护的欧洲核苷酸档案库（European Nucleotide Archive，ENA）、NCBI 维护的 GenBank 和日本国立遗传学研究所维护的 DDBJ（DNA Data Bank of Japan）。三家于 1988 年达成协议，组成国际核苷酸序列数据库合作联盟（International Nucleotide Sequence Database Collaboration，INSDC），每天交换数据，执行统一的数据标准。所以理论上三库内容相同，只是同步存在时间差。【已核实】INSDC 官网列出的成员至今仍只有这三家机构；按数据类型，读段归 SRA（NCBI、DDBJ）和 ENA，组装序列归 DDBJ、ENA、GenBank，样本和项目元数据归 BioSample 和 BioProject。

教材把 GSA（Genome Sequence Archive）称为”继 GenBank、ENA、DDBJ 之后的第四个核酸序列公共数据库”，这一点需要纠正【易错】。GSA 原文对自己的定位是”a data repository for archiving raw sequence data”，按 INSDC 的数据模型（BioProject、BioSample、Experiment、Run）组织原始读段，是 INSDC 的补充而不是成员（Wang et al., 2017）【已核实】；它对应的是 SRA，不是 GenBank。国家基因组科学数据中心后来扩展出 GSA-Human、OMIX（Chen et al., 2021），2024 年发表的 GenBase 才是对应 GenBank 的核苷酸序列库，并已与 GenBank 建立数据交换（Bu et al., 2024）【已核实】。

RefSeq 与 INSDC 的关系是 CS 读者最需要弄清的一点。GenBank 等 INSDC 库存的是作者递交的原始记录，”由作者负责，NCBI 不改动”；同一个基因可能有几十条来自不同实验室的记录，注释质量不一。RefSeq（Reference Sequence）由 NCBI 在 INSDC 数据的基础上为每个物种的每种分子挑选或构建一条代表序列，统一校验和注释。RefSeq 发布说明把这种关系比作”综述文章与原始论文”：RefSeq 是对原始数据的综合和总结，INSDC 仍是一手档案【已核实：RefSeq Release 237 发布说明】。RefSeq 所说的”非冗余”指每个物种、每种生物分子一个代表，而不是全库去同源。

RefSeq 的 accession 一律带下划线，INSDC 的 accession 从不含下划线，这是区分两者最快的办法。常见前缀如下（RefSeq Release 237 发布说明 3.8 节）【已核实】：

RefSeq 记录还带状态码，从高到低大致是 REVIEWED、VALIDATED（经过人工审阅），PROVISIONAL、PREDICTED、INFERRED、MODEL（未经人工审阅）。做”可信训练集”时，状态码比前缀更能说明一条记录的可靠程度。

【易错】Release 135 那一行最容易读错。WGS（whole genome shotgun）记录是基因组鸟枪法测序的组装结果（contig、scaffold），TSA（transcriptome shotgun assembly）是转录组组装结果，两者本身就是”组装过的序列”，不是原始读段。ENA 的季度发布（release）一直是”组装/注释序列的快照”，Release 135 起把按项目组织的 WGS、TSA 序列集合移出了这个快照，改在单独的 FTP 目录按项目持续分发（ENA Release 143 发布说明：”WGS and TSA sets are not included in the release and can instead be obtained from…”）【已核实】。原始读段从来不在这个快照里。因此：

  • 表 3.5 中 134 → 135 记录数降到 21.5%、核苷酸数降到 9.3%，说明当时 WGS + TSA 约占记录数的 78.5%、核苷酸的 90.7%，这正是”鸟枪法数据占一半以上”的体现；
  • 此后”存储增长变缓”是统计口径变了，不是 ENA 存的数据变少了。

GenBank 的做法相同：Release 274.0（2026-10-15）的传统记录有 2.70 亿条、9.38 万亿 bp，而按项目分发的 WGS/TSA/TLS 集合有 67.4 亿条、56.0 万亿 bp，后者是前者的 6 倍【已核实：GenBank 发布说明】。【现代实践】ENA 的季度发布在 Release 143（2020 年 3 月）之后停止，此后数据通过浏览器、FTP 和 API 每日持续分发（ENA Release 143 发布说明）【已核实】，教材表 3.5 的 Release 142 已是倒数第二版。

Rfam 与 Pfam 的对比是这一节最值得理解的内容【重点】。蛋白家族成员之间序列相似性可以较高，Pfam 用 profile HMM 描述一个家族的序列特征；RNA 的功能更多依赖二级结构，同一家族的 RNA 常常是结构保守而序列差异大。碱基配对的两侧会发生协同突变（一侧 G→A 时另一侧 C→U，配对仍然保持），这种”协变”是 RNA 家族的标志。Rfam 用协方差模型（covariance model，CM）描述家族：它在 profile HMM 的基础上对配对位点做联合建模，相当于一个带位置特异参数的随机上下文无关文法，所以能利用协变信息搜索结构同源物。代价是计算复杂度高得多（第 9 章）。

RefSeq 与 Gene

RefSeq 已在 §3.1 讨论。Gene 数据库以基因为记录对象，汇集基因的序列、位置、名称、功能和文献链接。教材给出的规模是 5300 多个物种的 430 万条基因记录；2026-10-22 E-utilities 显示 Gene 库有约 1.01 亿条记录（§7.3），说明这类数字需要随时查新。

BUSCO

BUSCO（Benchmarking Universal Single-Copy Orthologs）基于 OrthoDB 直系同源数据库，为各个类群挑出”几乎在所有成员里都存在、并且只有一份”的直系同源基因集。它最重要的用途是从基因内容的角度评价一个基因组组装、注释或转录组的完整度：如果组装得完整，这些基因应当绝大多数能找到且只出现一次。教材举的植物数据集含 1440 个基因（基于 30 个植物基因组）；数据集随 OrthoDB 版本更新，具体基因数以所用数据集为准。CEGMA 是更早的同类方法，基因集更小。

BUSCO 的结果分四类：完整且单拷贝（S）、完整但多拷贝（D）、片段化（F）、缺失（M），通常写成 C:..%[S:..%,D:..%],F:..%,M:..%,n:..，其中 C = S + D。D 偏高提示组装里有冗余的单倍型或重复拼接；F、M 偏高提示组装破碎或不完整。

【现代实践】教材描述的”先 AUGUSTUS 从头预测、再 HMMER3 比对”是早期版本的流程，且漏了先用 tBLASTn 定位候选区域的一步。BUSCO 用户指南与更新日志显示：v5.0.0 起默认用 MetaEuk 取代 AUGUSTUS；v5.7.0 起真核基因组模式默认用 miniprot（一个把参考蛋白比对到基因组上的工具，而不是从头预测器），AUGUSTUS 和 MetaEuk 改为选项；原核基因组用 Prodigal 预测基因；所有模式最后都用 HMMER3 对各 BUSCO 的 profile HMM 打分并分类【已核实】。当前大版本是 v6（Tegenfeldt et al., 2025）。BUSCO 还提供病毒数据集，并能用于宏基因组分箱的质量评价（Manni et al., 2021）。

Gene Ontology

GO（Gene Ontology）是描述基因产物属性的标准词汇表，分三个方面：分子功能（molecular function）、细胞组分（cellular component）和生物学过程（biological process）。每个术语（教材称”节点”）有名称和唯一编号，如 GO:0003723 是”RNA binding”【已核实：QuickGO】。

两点教材没有展开、但用 GO 做分析或训练模型时必须知道的事：

  • GO 的结构是有向无环图，一个术语可以有多个父术语（GO 官方文档）【已核实】。沿 is_a 关系向上，GO:0003723 RNA binding 的祖先是 nucleic acid binding、binding，最后到 molecular_function。注释有”真路径规则”：基因注释到一个术语，就隐含注释到它的所有祖先。所以 GO 预测是一个层级多标签分类问题，评测时要先把注释沿图传播。
  • 每条 GO 注释都带证据码。IDA 等实验证据码表示有实验支持；IEA（inferred from electronic annotation）是自动注释，未经人工审核，主要来自同源推断（InterPro 签名映射、UniProt 关键词映射、Ensembl 直系同源转移）（GO 证据码文档）【已核实】。教材说对未知基因”在 UniProt 中确定同源蛋白、从中得到注释”，这正是 IEA 的产生方式。训练”序列 → GO”模型时如果把 IEA 当作标签，模型学到的很大程度上就是同源推断规则本身（§8.2）。

4.2 蛋白质结构数据库：PDB、SCOP、CATH【必须掌握】

实验结构：PDB

PDB（Protein Data Bank）20 世纪 70 年代建于美国 Brookhaven 国家实验室，1998 年起由 Rutgers 大学、圣迭戈超级计算机中心和美国国家标准与技术研究院共同组成的结构生物信息学研究合作组织（RCSB）负责（Berman et al., 2000）。教材给出的规模是 2020 年 7 月 166 594 个结构，其中蛋白质结构 154 562 个。PDB 与欧洲的 PDBe、日本的 PDBj 组成全球蛋白质结构数据库联盟 wwPDB，联盟章程签于 2003 年，现有成员还包括核磁共振数据库 BMRB 和电镜数据库 EMDB【已核实：wwPDB 网站】。

【现代实践】2026-10-23 RCSB 检索接口显示 PDB 有 261 139 个实验结构，其中 X 射线衍射 208 325 个、电镜 37 405 个、溶液核磁共振 14 751 个；RCSB 网站另外托管了约 106 万个计算模型（来自 AlphaFold DB 等），检索时要注意区分【已核实】。文件格式方面，PDBx/mmCIF 已是标准格式；wwPDB 公布 2027 年 7 月 21 日起只发放 12 个字符的扩展 PDB ID（形如 pdb_00001abc），同时以只含 PDBx/mmCIF 的新档案结构取代现有档案【已核实：wwPDB 新闻，2026-07-20】。写解析代码时不要再假定 PDB ID 一定是 4 个字符。

HSSP 存放 PDB 中每个已知结构的蛋白与其序列同源物的多序列比对结果，依据是”序列同源的蛋白很可能有相同的三维结构”，这也是同源建模的基本假设。

4.3 蛋白质组数据库【了解即可】

蛋白质组（proteome）指一个基因组所表达的全部蛋白质，这个词由 Marc Wilkins 提出（教材记为 1995 年）；蛋白质组学（proteomics）是研究蛋白质组的学科，Peter James 1997 年提出这个名称。教材把蛋白质组学的含义写成了”一种基因组所表达的全套蛋白质”，混淆了两个概念。PRIDE 是 EBI 的质谱蛋白质组学数据库，存放蛋白与肽段鉴定结果、翻译后修饰和支持它们的质谱证据；教材图 3.16 的截图显示它是 ProteomeXchange 联盟的核心成员，质谱数据经该联盟统一递交。

4.4 蛋白质功能域数据库：PROSITE、Pfam、InterPro【必须掌握】

功能域（domain）是蛋白序列中一段保守、能相对独立地折叠和行使功能的区域，长度从约 25 到 500 个氨基酸不等。进化中功能域可以作为单元被重组，同一个功能域出现在许多不同的蛋白里，所以按功能域注释比按全长序列注释更细致。

PROSITE 收录有生物学意义的位点和序列模式，以及由多序列比对构建的概型（profile）。模式用一种类似正则表达式的语法书写（PROSITE 用户手册）：x 表示任意残基，[ST] 表示 S 或 T，{P} 表示除 P 以外，x(2,4) 表示 2 到 4 个任意残基，元素之间用 - 连接，句点结束。例如 N-糖基化位点 PS00001 的模式是 N-{P}-[ST]-{P}.，等价于正则 N[^P][ST][^P]【已核实：PROSITE 条目】。这个模式只有四个位置，随机命中的机会很高：§7.6 在 AXL2 蛋白（823 aa）上找到 21 处，按该蛋白自身的氨基酸组成估计随机期望约 12.6 处。PROSITE 给这类条目加了 /SKIP-FLAG=TRUE，用户手册解释说，像 N-糖基化这样的常见修饰位点在大多数已知蛋白里都能找到，程序可以选择忽略它们。概型（profile）为每个位置给出各残基的打分，比模式更敏感，能发现序列整体相似度很低、只保留了功能区特征的远缘成员。

Pfam 是蛋白家族库，每个家族由人工挑选的种子比对（seed alignment）和由它训练的 profile HMM 构成，用 HMM 在序列库中搜索得到完整比对；相关的家族归为更高一级的 clan。教材给出的是 Pfam 33.1（2020 年 5 月）：18 259 个条目、635 个 clan，并区分高质量、人工注释的 Pfam-A 和自动生成、低质量的 Pfam-B。

【现代实践】Pfam 的情况变化很大。InterPro 2022 年的论文宣布 Pfam 网站将于 2022 年底停用，Pfam 2025 年的论文报告网站已停用、数据并入 InterPro 网站提供（Paysan-Lafosse et al., 2023、2025）【已核实】。Pfam-B 在 28.0 到 33.0 版之间停发，33.1 起只以比对压缩包形式提供，每版重新生成、没有注释；Pfam 从 29.0 版起基于 UniProtKB 参考蛋白质组构建（Pfam 38.2 发布说明）【已核实】。当前版本 38.2 有 30 134 个家族、891 个 clan【已核实：Pfam FTP 与 InterPro API】。Pfam 团队还开发了用深度学习扩展家族覆盖的 Pfam-N，使 UniProtKB 的覆盖率比标准 Pfam 提高 8.8%，并借助 AlphaFold 模型修正结构域边界、发现新家族（Paysan-Lafosse et al., 2025）【已核实】。

InterPro 把多个成员数据库中描述同一家族、结构域或位点的签名整合成一个条目，并附上描述、文献和 GO 映射，InterProScan 是它的扫描软件（Blum et al., 2021）。教材列出的成员是 PROSITE、Pfam、ProDom、PRINTS、SMART 等。2026-09 的 InterPro 110.0 成员库为 Pfam、PROSITE（模式与概型）、PRINTS、SMART、PANTHER、NCBIfam、CATH-Gene3D、SUPERFAMILY、PIRSF、HAMAP、SFLD、CDD 和 AntiFam，ProDom 已不在其中【已核实：InterPro API】。

从计算的角度看，这里有两种匹配范式【重点】。PROSITE 模式是正则表达式式的硬匹配：要么匹配要么不匹配，没有分数，短模式的随机命中率高。profile 和 profile HMM 是软匹配：每个位置有残基分布和插入、缺失的概率，给出对数几率分数和 E 值，能发现远缘成员。两者的算法细节在第 5 章（profile、profile HMM）和第 14 章（HMM）。

6. 统计模型与算法推导

6.1 Phred 与 Solexa 质量值

由式（3.1），Phred 分数 \(Q_p=-10\log_{10}e\)。Solexa 分数用的是错误的几率（odds）而不是概率：

\[ Q_s = -10\log_{10}\frac{e}{1-e} \]

两者互换：由 \(10^{-Q_p/10}=e\) 得 \(\frac{1-e}{e}=10^{Q_p/10}-1\)，所以

\[ Q_s = 10\log_{10}\bigl(10^{Q_p/10}-1\bigr), \qquad Q_p = 10\log_{10}\bigl(10^{Q_s/10}+1\bigr) \]
\(e\) 很小时 \(1-e\approx 1\)，两者几乎相等（Q30 时差 0.004）；\(e=0.5\) 时 \(Q_p\approx3.01\) 而 \(Q_s=0\)。所以把 Solexa 数据当 Phred 读，只在低质量端出错，但质量过滤恰恰发生在低质量端。

一条长 \(L\) 的读段，若各碱基错误独立，则期望错误数和”完全无错”的概率分别为

\[ \mathbb{E}[\text{错误数}] = \sum_{i=1}^{L} 10^{-Q_i/10}, \qquad P(\text{无错}) = \prod_{i=1}^{L}\bigl(1-10^{-Q_i/10}\bigr) \]

一条 150 bp、每个碱基都是 Q30 的读段，期望有 0.15 个错误碱基，完全正确的概率约为 \(0.999^{150}\approx0.86\)。

6.2 去冗余：贪心增量聚类与短词过滤

CD-HIT 的做法（CD-HIT 用户手册）【已核实】：把序列按长度从长到短排序，依次处理；第一条成为第一个簇的代表；之后每条序列与已有的代表比较，与某个代表的一致性达到阈值就并入（默认快速模式并入第一个满足阈值的代表，精确模式并入最相似的代表），否则自己成为新代表。默认的”一致性”是比对中相同残基数除以较短序列的全长。最坏情况下比较次数是 \(O(NK)\)，\(N\) 为序列数，\(K\) 为簇数；去冗余阈值高时 \(K\) 接近 \(N\)，整体接近 \(O(N^2)\)。

加速的关键是短词过滤（short word filter）：两条序列要达到某个一致性，就必须共享足够多的相同 \(k\)-mer，共享数不够就不必做比对。在只有替换、没有插入缺失的情形下这个下界可以严格推出：长 \(L\) 的两条等长序列若有 \(m\) 个错配，每个错配最多破坏覆盖它的 \(k\) 个 \(k\)-mer，所以共享的 \(k\)-mer 至少有

\[ (L-k+1) - k\,m, \qquad m \le \lfloor (1-t)L \rfloor \]

个，其中 \(t\) 是一致性阈值。\(t\) 越低，下界越小，当 \((1-t)\,k\,L \ge L-k+1\)，即大约 \(t \le 1-1/k\) 时下界变为非正，过滤失效。§7.5 的模拟里，\(t=0.9\)、\(k=5\) 时过滤掉了 99% 以上的比较；\(t=0.5\)、\(k=2\) 时下界为 −1，过滤完全不起作用。CD-HIT 用户手册推荐的词长（如 0.7–1.0 用 5，0.5–0.6 用 3，0.4–0.5 用 2）比这个最坏情况的下界激进，因为它依据的是真实比对中共享词数的统计分布，换来速度，也承担漏判的风险；手册同时说明短词过滤在更低的阈值下不能使用。

MMseqs2 的 Linclust 进一步把聚类做到与 \(N\) 呈线性：先按共享的 \(k\)-mer 把序列分组，每组只和一个中心序列比，运行时间不再依赖簇数 \(K\)；原文在单台服务器上用 10 小时把 16 亿条宏基因组片段聚类到 50% 一致性（Steinegger & Söding, 2018）【已核实】。UniRef90/50 和 NCBI 的 ClusteredNR 都用 MMseqs2 聚类（§2.3、§4.1）。

6.3 Mash 距离：用 k-mer Jaccard 估计核苷酸分歧度

Mash（Ondov et al., 2016）把两个基因组的 \(k\)-mer 集合的 Jaccard 指数 \(J\) 换算成每个位点的替换率【已核实：原文 Methods】。设每个位点以概率 \(d\) 发生替换且相互独立，一个 \(k\)-mer 不含任何替换的概率为 \((1-d)^k\approx e^{-kd}\)（泊松近似），它等于两个基因组共享的 \(k\)-mer 占比 \(w/n\)（\(n\) 为平均 \(k\)-mer 数）。Jaccard 指数 \(J=\frac{w}{2n-w}\)，由此 \(\frac{w}{n}=\frac{2J}{1+J}\)，于是

\[ D = -\frac{1}{k}\ln\frac{2J}{1+J} \]

原文报告 \(D\approx 1-\text{ANI}\)，并用 \(D\le0.05\) 对应 ANI ≥ 95% 来划分物种簇。§7.5 用 20 kb 随机序列验证：替换率 ≤ 10% 时 \(D\) 与真值吻合；20% 时 \(D\) 偏高，且 \(k=21\) 时 \(J\) 已降到 0.005，估计变得不稳定。所以 \(k\)-mer 方法适合判断”是否近乎重复”（如病毒 vOTU 的 95% ANI 去重），不适合度量远缘关系。

6.4 倍增时间

若数据量从 \(N_0\) 增长到 \(N_1\) 用了 \(\Delta t\)，按指数增长计算的倍增时间为

\[ T_d = \frac{\Delta t}{\log_2(N_1/N_0)} \]

用表 3.5 的数据逐段计算（§7.4），可以看到倍增时间随时期变化，教材的”22 个月”只是一个粗略的平均。

6.5 短模式的随机命中

若一个长度为 \(k\) 的模式第 \(j\) 个位置允许的残基集合为 \(S_j\)，各位置独立、残基频率为 \(f_a\)，则任一起点随机命中的概率和长 \(L\) 的序列中的期望命中数为

\[ p = \prod_{j=1}^{k}\sum_{a\in S_j} f_a, \qquad \mathbb{E}[\text{命中数}] = (L-k+1)\,p \]

PS00001（N-{P}-[ST]-{P}）在 AXL2 的组成下 \(p\approx0.0154\)，823 个残基中期望约 12.6 处（§7.6）。位置不独立、序列组成不均匀时，用打乱序列得到的经验分布比这个公式更可靠。

这个模拟回答一个问题：同一个模型、同样多的训练数据，随机划分和按序列一致性聚类划分得到的测试成绩差多少，哪一个更接近部署到新数据时的真实表现。为了让”一致性”不依赖比对，模拟只用替换突变；”模型”是最简单的按一致性找最近邻。

结果可以这样读：

  • 随机划分时，每条测试序列在训练集里几乎都有同一亚家族的”兄弟”（最高一致性 0.92），准确率 1.000；同一个模型拿到新出现的亚家族上只有 0.764。随机划分把性能高估了约 0.24。

8.2 评测与数据泄漏【AI4S】

教材说冗余会”使预测方法发生偏离”，落到机器学习评测上就是数据泄漏。

  1. 按同源性划分。先用 CD-HIT 或 MMseqs2 按一致性聚类，再以簇为单位划分训练、验证和测试集。阈值要与任务匹配：想评价对新亚家族的泛化，就按亚家族之间的一致性（如 30%–50%）聚类；想评价远程同源检测，就按 SCOP/CATH 的折叠或超家族整组留出。§7.5 的模拟说明随机划分可以把准确率从约 0.7 抬到 1.0。真实数据中的例子：Bernett et al.（2024）发现，序列型蛋白互作预测模型在随机划分下成绩很高，把训练集与测试集的序列相似性降到最低后，表现接近随机，模型主要学到的是序列相似性和节点的度【已核实】。
  2. 最优划分是 NP 难问题。在保持各类别比例、各集合大小的同时让训练集与测试集之间的相似度最小，可以写成组合优化问题；DataSAIL 证明了它是 NP 难的，并用聚类加整数线性规划的启发式求解（Joeres et al., 2025）【已核实】。实际工作中通常接受”聚类后整簇随机分配”这一近似。
  3. 标签泄漏。用 IEA 注释做 GO 标签、用含文本挖掘通道的 STRING 边做互作标签，模型可能只是在重现产生这些标签的规则。至少要报告只用实验证据标签时的结果。
  4. 版本与时间。数据库会删改条目（UniProtKB 2026 年改版）、会修正污染（Conterminator、FCS-GX）、分类体系会变（ICTV 每年更新）。训练集和测试集要来自同一版本或明确的时间切分（用某日期之前的数据训练、之后新增的数据测试），并在论文中写明发布号。
  5. 报告规范。ELIXIR 的 DOME 建议从数据（Data）、优化（Optimization）、模型（Model）、评估（Evaluation）四方面报告监督学习方法（Walsh et al., 2021），其中数据部分要求说明训练集和测试集如何划分、是否独立。

9. 与 VirusBin 的联系

这一章和你的课题有三处真实的联系：病毒参考序列从哪里来、它们有什么偏差，以及评测时怎样避免参考库与评测数据之间的泄漏。

  1. 病毒序列的来源与规模。INSDC 把病毒记录归在 VRL 和 PHG 两个分类群；2020 年 1 月 ENA 的 VRL 有 310 万条记录、平均每条只有约 1.6 kb，PHG 只有 1.7 万条、平均约 37 kb（§3.3、§7.4），说明公共库里的病毒序列以单个基因或片段为主，完整噬菌体基因组很少。2026-10 NCBI 核酸库中病毒界的记录约 1528 万条，其中 RefSeq 只有 19 655 条（§7.3）；RefSeq Release 237 的 viral 目录涵盖 15 395 个物种（分类单元）【已核实】。NCBI 的病毒基因组资源为每个病毒物种整理参考基因组（Brister et al., 2015）。宏基因组来源的病毒序列主要在 IMG/VR：第 4 版有 1500 多万条病毒基因组与片段，聚成 870 万个 vOTU，其中 231 408 个至少有一个高质量代表，序列用 geNomad 识别、CheckV 评估质量（Camargo et al., 2023）【已核实】。分类以 ICTV 为准，当前为 MSL41（2025）；2022 年 ICTV 废除了按形态划分的有尾噬菌体科（Myoviridae、Siphoviridae、Podoviridae）和 Caudovirales 目，并改用双名法种名（Turner et al., 2023）【已核实】。

  2. 参考库偏差对分箱评测意味着什么。RefSeq 病毒和 ICTV 范例基因组集中在已分离培养、与病原或模式宿主相关的病毒，宏基因组里的大多数病毒与它们相距很远。具体影响：

    • 如果 5-mer 编码器的预训练或超参数选择用到了参考基因组，评测样本里与参考库相近的 contig 会表现得更好。建议按”contig 与训练用参考序列的最高 ANI”分层报告错误合并率，至少分出 ≥95% ANI（同一 vOTU）和远缘两组。
    • UniProt 的病毒参考蛋白质组按 ICTV VMR 范例基因组选取，2025_04 起分类未定种（如”某某 sp.”）的条目移出 UniProtKB，只留在 UniParc（§4.1）。如果流程里用 TrEMBL 或 UniRef 的病毒蛋白做注释特征（如数标志基因），2025 年前后下载的库会给出不同结果，要写明版本，必要时改用 UniParc 或 IMG/VR 的蛋白。
    • 你用同一样本的配对长读长组装构建真值，这避开了参考库偏差，是方法上的优点；但长读长组装本身也可能有嵌合或污染，用作真值前值得做一遍污染与完整度检查。

  3. 去冗余与防泄漏。病毒基因组的去冗余通用”95% ANI、85% 对齐比例”划 vOTU。CheckV 的做法是贪心的中心聚类：按长度排序，最长者为中心，把与它在 95% ANI 和 85% AF 以内的基因组归入同簇，重复直到全部归类；评测完整度估计时，先从参考库里删去与测试序列 >95% AAI 的近缘序列（Nayfach et al., 2021）【已核实】。这和 §6.2 的 CD-HIT 是同一个算法框架，也和 §8.2 的”按簇划分”是同一个原则。如果 VirusBin 的对比学习编码器在一批病毒基因组上训练，又在另一批样本上评测，两批之间应先用 Mash 或 ANI 去掉近乎相同的基因组（\(D\le0.05\) 大致对应 ANI ≥ 95%，§6.3），否则对比学习的”正样本对”可能在测试集里原样出现。

  4. 格式上的小坑。许多噬菌体和小病毒基因组是环状的：GFF3 规定跨越原点的特征 end 写成”原点后位置 + 序列全长”，并给序列标 Is_circular=true（§2.2）；GenBank 的 LOCUS 行会标 circular。基于 contig 的工具常把环状基因组在任意位置切开，一个跨越切点的基因就会变成两个”部分特征”（<、>），评测基因层面的完整度时要考虑这一点。

10. 教材习题解答

习题 1：什么是一级数据库和二级数据库？它们有什么异同？

一级（初级）数据库直接收存实验产生的序列或结构及其基本注释，如 GenBank/ENA/DDBJ（核酸序列）、PDB（实验结构）；教材把 Swiss-Prot 也列为蛋白序列的初级库。二级数据库在初级数据和文献的基础上加工、归纳，带有特定的生物学目的，如 RefSeq（每个物种每种分子一条整理过的参考序列）、Pfam（蛋白家族的比对与 HMM）、GO（功能本体）、KEGG（通路）。

相同点：都以记录为单位，有稳定的标识符和版本，都需要注释，都会持续更新。不同点：初级库追求完整、保留原貌，内容由递交者负责，冗余多、注释质量参差；二级库追求准确和可用，由数据库方整理，去掉冗余、统一注释，但覆盖面依赖初级库，且带有整理者的判断（如家族边界、参考序列的选择）。两者之间还有一层”整理过的参考库”（RefSeq、Swiss-Prot），它们既不是原始档案，也不是功能知识库（§1 的分层表）。使用时，追溯原始证据看初级库，做注释和分析用二级库，并都记下版本。

习题 2：简述 FASTA 和 FASTQ 格式，并比较它们的异同。

FASTA：每条记录由 > 开头的描述行和若干行序列组成，描述行第一个空白前通常是 ID。FASTQ：每条读段固定四行，@ 开头的读段名、序列、+ 开头的分隔行、与序列等长的质量字符串，质量字符按 \(Q=-10\lg e\) 编码并加 ASCII 偏移（现行为 +33）。

FASTA FASTQ
内容 序列（核酸或蛋白） 序列 + 每个碱基的质量值
记录头 > @
行数 序列可分多行 固定 4 行（规范允许多行，实际几乎不用）
典型用途 参考序列、组装结果、蛋白库 测序原始读段
解析要点 描述行格式不统一 校验 + 行和等长；判断质量编码

相同点：都是纯文本、都以字母表示残基、都可以多条记录连写。FASTQ 可以无损地转成 FASTA（丢掉质量），反过来不行。

习题 3：如何向 NCBI 递交序列？列举三种方法。如果序列文件数据很大或序列条数很多，应该如何解决？

教材列出的方法有 BankIt、Sequin、tbl2asn、Submission Portal、Barcode Submission Tool。按现状（GenBank Release 274.0 发布说明与 NCBI Insights）【已核实】：

  1. BankIt：网页表单，适合少量序列，可逐条填写注释。
  2. Submission Portal：网页递交系统，适合高频类型（如 16S rRNA、rRNA-ITS、COX1、SARS-CoV-2）以及基因组、SRA 等各类递交。
  3. table2asn：命令行工具，由序列文件（FASTA）和特征表批量生成递交用的 ASN.1 文件，用于完整基因组和大批量序列，生成后通过 Submission Portal 上传（必要时发邮件给 gb-sub@ncbi.nlm.nih.gov）。它取代了已过时的 tbl2asn；Sequin 已于 2021 年 1 月停用，注释基因组可用 Genome Workbench 的提交向导准备。

数据很大或条数很多时：不要用网页逐条填写，用 table2asn 批量生成并通过 Submission Portal 上传；原始测序数据不交 GenBank，而是作为 SRA 递交，大文件用 Submission Portal 提供的预上传通道；同一项目的读段、组装和注释通过 BioProject、BioSample 关联。递交前先做载体与污染筛查（VecScreen；基因组用 FCS），否则会被退回。

习题 4：如何下载水稻基因组的特定区段序列或注释？

先确定组装版本（教材图 3.8 中 Ensembl Plants 的粳稻为 IRGSP-1.0），因为坐标只在同一版本内有意义。

  • 网页：在 Ensembl Plants 的基因组浏览器中跳到目标区段，用导出功能下载该区段的序列（FASTA）和特征（GFF3）；批量查询可用 BioMart。
  • 程序接口：Ensembl REST API 可以直接按区段取序列，例如下面的请求返回 1 号染色体 100001–100060 位的正链序列（2026-10 实测可用，返回的描述行为 chromosome:IRGSP-1.0:1:100001:100060:1）：
  • 本地：下载整个基因组 FASTA 和注释 GFF3，用 samtools faidx genome.fa 1:100001-100060 取序列（区段写法为 1-based 闭区间），用 awk -F'\t' '$1=="1" && $4<=100060 && $5>=100001' annotation.gff3 取与该区段重叠的特征；坐标若要交给 BED 工具，起点减 1（§2.1）。

习题 5：如何对 PDB 数据库记录进行三维结构的可视化？

  1. 网页：RCSB PDB、PDBe 的条目页内嵌 Mol* 查看器（Sehnal et al., 2021）【已核实】，可以直接旋转、选择链和配体、按二级结构或 B 因子着色。
  2. 桌面软件：下载条目的 PDBx/mmCIF 文件（2027 年起新条目只用扩展 ID 和 mmCIF），用 PyMOL、UCSF ChimeraX（Meng et al., 2023）等打开，可做表面、静电势、结构叠合与出图。
  3. 程序：用 Biopython 的 Bio.PDB 等库解析坐标，再交给 py3Dmol、nglview 之类的库在 Jupyter 中显示，适合批量处理。

看结构时要注意记录里的实验方法和分辨率，以及是否是生物学组装体（biological assembly）还是不对称单元；看 AlphaFold DB 的预测结构时要按置信度 pLDDT 着色，低置信区域不应当作结构证据。

习题 6：如何确定未知基因/序列属于哪个 KEGG 代谢途径？

KEGG 通路图上的节点是 KO（KEGG Orthology），所以关键是先给序列分配 KO。

  1. 若是核酸序列，先预测编码区并翻译成蛋白。
  2. 用 KEGG 提供的自动注释服务分配 KO：BlastKOALA（基于 BLAST 比对 KEGG GENES）、GhostKOALA（适合宏基因组的大批量序列）（Kanehisa et al., 2016），或 KofamKOALA（用 KO 特异的 profile HMM 和预先计算的阈值）（Aramaki et al., 2020）【已核实】。教材说的”通过 BLAST 比对查询”就是这一步的早期做法。
  3. 把得到的 KO 列表提交 KEGG Mapper，查看它们落在哪些通路图和模块上。
  4. 解释时注意：KO 分配是同源推断，单个 KO 落在某条通路上不等于这条通路存在；对一个完整基因组，应看通路或模块中的 KO 是否大部分齐全。

11.3 参考答案

  1. INSDC 是作者递交的组装/注释序列的一手档案，内容由递交者负责，数据库不改动；RefSeq 是 NCBI 在 INSDC 基础上为每个物种每种分子整理的参考序列；Swiss-Prot 是 UniProt 人工审阅的蛋白条目。后两者都属于”整理过的参考库”，内容由数据库方负责。
  2. accession 是稳定的记录号；accession.version 指向一条特定的序列，序列每改一次版本号加 1。只改注释（如俗名）不改变版本号，图 3.4 的 U49845.1 就是例子。
  3. nr 只合并长度相同、逐位相同的序列，相差一个残基的同源序列仍各占一条。ClusteredNR 用 MMseqs2 按 90% 一致性、90% 长度聚类；UniRef90 用 Linclust 按 90% 一致性、对种子 80% 覆盖聚类，各取代表序列。
  4. GSA 是原始测序读段的归档库，对应 SRA，而不是 GenBank 那样的组装/注释序列库；INSDC 成员只有 DDBJ、EMBL-EBI、NCBI 三家。对应 GenBank 的国内库是 GenBase。
  5. 不是。WGS、TSA 本身就是组装好的序列，Release 135 起只是不再打包进季度发布快照，改为按项目单独分发；表 3.5 里数字的下降是统计口径变化。
  6. phase 是从本 CDS 片段 5′ 端起到下一个完整密码子起点要跳过的碱基数，相对于片段本身；frame 一般指一个碱基相对于整个 ORF 或密码子的位置。GTF 第 8 列名叫 frame，但定义与 GFF3 的 phase 相同。
  7. 前者使大家族在训练中占过多权重，造成加权偏差，对策是按簇加权或每簇取代表；后者使测试成绩高估泛化能力，对策是按一致性聚类后整簇划分。
  8. IEA 注释主要由同源推断自动产生，未经人工审核。模型用它当标签，学到的可能就是”同源即同功能”这条规则本身，评测成绩会虚高，对真正新颖的序列帮助有限。
  9. RNA 家族保守的是二级结构，配对位点会发生协同突变，序列可以差异很大。profile HMM 把各位置当作独立的，抓不住配对位点之间的协变；协方差模型对配对位点联合建模，才能利用这种信息。
  10. 不能。AlphaFold DB 的结构是用 PDB 训练出来的模型的预测，有 pLDDT/PAE 置信度；用它评价其他预测方法或作训练标签时，要考虑它与 PDB、与被评价方法之间的依赖关系。
  11. \(Q=-10\lg0.005=23.01\)，取 23，字符为 `chr(56)` = `8`；`#` 的 ASCII 码为 35，\(Q=2\)，错误率 \(10^{-0.2}\approx0.631\)。

12. 历史与人物

12.1 教材：分子数据库与戴霍夫和戈德

玛格丽特·戴霍夫（Margaret Oakley Dayhoff，1925–1983）是美国物理化学家，1948 年在哥伦比亚大学获量子化学博士学位，博士期间就用穿孔卡片机计算有机分子的共振能。此后在洛克菲勒研究所、马里兰大学从事研究，其间因家庭离开研究数年；1959 至 1960 年间加入罗伯特·莱德利（Robert Ledley）创办的国家生物医学研究基金会（NBRF），任副主任 21 年。她与莱德利 1962 年发表了蛋白测序辅助程序 COMPROTEIN（教材误印为 COMPORTEIN），被视为最早的生物信息学软件之一；1965 年与 Eck 等出版《蛋白质序列和结构图谱》（Atlas of Protein Sequence and Structure），收录当时已知的全部蛋白序列（Wikipedia 记为 65 条；教材写作”65 个家族”【需查证】），这是第一个分子数据库，之后多次再版，1978 年的版本已附数据磁带。为了压缩数据，她推动了氨基酸单字母代码，后被 IUPAC-IUB 采纳；她用收集的序列重建系统发育关系，建立了 PAM 替换矩阵（第 4 章）。她于 1983 年 2 月 5 日因心脏病去世，享年 57 岁（教材作 58 岁，有误）。次年，莱德利与 Winona Barker 基于她的数据库建立了 PIR。NCBI 前主任 David Lipman 称她为”生物信息学之母与之父”。教材还提到，她收集序列的工作当年并不被看好，常被视为”19 世纪式的编目”。

沃尔特·戈德（Walter Goad，1925–2000）是洛斯阿拉莫斯国家实验室的核物理学家。他出身工人家庭，12 岁就为无线电修理工做事；1953 年在杜克大学获物理学博士，读博期间随导师 Nordheim 到洛斯阿拉莫斯参与氢弹研制。20 世纪 60 年代转向分子生物学，1974 年成为实验室理论生物学与生物物理组（T-10）的核心成员，组内有 Temple Smith、Mike Waterman、Minoru Kanehisa（后来的 KEGG 创始人）等。1979 年他建立 Los Alamos Sequence Database，1982 年在 NIH 资助下发展为 GenBank，他的团队运营 GenBank 至 1987 年，并与 EMBL、DDBJ 建立了合作，促成了国际核苷酸数据库的联合。戴霍夫的蛋白质图谱与戈德的核酸库被视为现代分子序列数据库的两个源头。

13. 全章速记

  1. 数据库的层次：原始读段（SRA/ENA/GSA）→ INSDC 组装与注释序列（GenBank/ENA/DDBJ）→ 整理过的参考（RefSeq、Swiss-Prot、UniRef）→ 衍生知识库（Pfam/InterPro、GO、KEGG、STRING）；另有预测结构库（AlphaFold DB）。
  2. INSDC 只有 DDBJ、EMBL-EBI、NCBI 三家，每日交换数据；GSA 是原始读段库，不是第四个成员；国内对应 GenBank 的是 GenBase。
  3. RefSeq 带下划线前缀（NM_、NP_、NC_、XM_、WP_ 等），INSDC accession 不带下划线；RefSeq 是对 INSDC 的整理，INSDC 记录不被改动。
  4. 引用序列用 accession.version；版本号只随序列变化，GI 号已退出。
  5. FASTA 意为 FAST-All，不是”A 表示联配”；描述行格式不统一，ID 取第一个空白前。
  6. FASTQ 四行、+ 不可省、序列与质量等长；\(Q=-10\lg e\)；现行 Phred+33；Illumina 1.3–1.7 是 Phred+64，Solexa 用几率定义的分数。
  7. 表 3.2：Q13/.、Q20/5、Q30/?、Q40/I，全部正确。Q30 比例是质量 ≥30 的碱基占比，不是错误率。
  8. GFF3：9 列 Tab 分隔、1-based 闭区间、strand 可为 . 或 ?、CDS 必须给 phase；phase ≠ frame；##FASTA 之后是序列。
  9. GTF：第 8 列叫 frame 但含义同 phase；CDS 不含终止密码子；gene_id、transcript_id 必填。
  10. BED 是 0-based 半开区间：由 GFF 转 BED，起点减 1。
  11. GBFF：LOCUS 行按空白分词；<、> 表示部分特征；complement、join；/codon_start = phase + 1；以 // 结尾。
  12. nr 只合并完全相同的序列；ClusteredNR（90%/90%）2025 年起是蛋白 BLAST 默认库；UniRef90/50 用 Linclust，要求对种子 80% 覆盖。
  13. 冗余有两种害处：训练集内的加权偏差，训练测试间的同源泄漏；后者要按聚类划分（§7.5：随机划分 1.000 对按簇划分 0.681）。
  14. ENA Release 135 起 WGS、TSA 集合移出季度发布快照，不是”放弃存储”；Release 143（2020）后季度发布停止。
  15. 表 3.7 的记录数合计含 CON，核苷酸合计不含 CON；”每 22 个月翻一番”只是粗略说法。
  16. NONCODE 不收 tRNA 和 rRNA（教材自相矛盾）；Rfam 用协方差模型，因为 RNA 家族保守的是二级结构。
  17. BUSCO：完整单拷贝、完整多拷贝、片段化、缺失四类；现行版本真核基因组默认用 miniprot，不再是 AUGUSTUS。
  18. GO 是有向无环图，注释沿图向上传播；IEA 是未经审核的同源推断。
  19. UniProtKB 2025–2026 改为只收参考蛋白质组，TrEMBL 从约 2.5 亿降到约 1.5 亿条；被删条目在 UniParc。
  20. SCOP 主要人工，CATH 半自动（C、A、T、H）；PDB 约 26 万个实验结构，2027 年起用 12 字符 ID；AlphaFold DB 是 2021 年 7 月之后的预测结构库。
  21. Pfam 网站已并入 InterPro，Pfam-B 不再是教材描述的 ADDA 产物；ProDom 已不在 InterPro 成员中；PROSITE 短模式随机命中率高。
  22. 戴霍夫享年 57 岁，程序名 COMPROTEIN；STRING 最初由 EMBL 建立。
